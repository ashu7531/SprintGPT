## 2. Where Data is Stored & Retrieved

### 🗄️ Supabase PostgreSQL
We store persistent data here. It is configured with **PGVector** for vector embeddings:
* **`user_configs` table:** Stores user-configured Azure DevOps details (`organization`, `project`, plaintext `pat` token). Each row is keyed by the user's Supabase `user_id`.
* **`document_chunks` table:** Stores RAG knowledge chunks. Columns include `organization`, `project`, `title`, `url`, `content` (plain text), and `embedding` (3072-dimensional vector generated by Gemini).

### ⚡ Upstash Redis Cache
We use Redis exclusively as a high-speed cache for Azure DevOps:
* **Purpose:** Azure DevOps APIs can be slow and are rate-limited. Redis caches search queries (e.g. WIQL queries, sprint/iteration listings, and work item JSON payloads).
* **TTL (Time to Live):** Cached items are stored with an expiration (e.g., 5–10 minutes) so subsequent identical queries return instantly without hitting the Azure DevOps network.

### 🌐 Azure DevOps (Source of Truth)
We do not store project tasks or board data. Whenever you ask for a task status or sprint summary, SprintGPT fetches it live using the user's PAT token.

## 3. Core Request Flows

### Flow A: Querying Sprints / Work Items (API Cache Flow)

```mermaid
sequenceDiagram
    participant User as React Frontend
    participant Go as Go Backend
    participant Redis as Redis Cache
    participant ADO as Azure DevOps API

    User->>Go: POST /api/v1/chat {"message": "Show sprint summary"}
    Note over Go: Intent detected as "sprint_summary"
    Go->>Redis: Check cache for Sprint Data
    alt Cache Hit
        Redis-->>Go: Return Cached JSON
    else Cache Miss
        Go->>ADO: GET /_apis/wit/wiql (Fetch IDs)
        ADO-->>Go: Return IDs
        Go->>ADO: GET /_apis/wit/workitems?ids=... (Fetch Details)
        ADO-->>Go: Return Work Items JSON
        Go->>Redis: Cache response for 5 minutes
    end
    Go-->>User: Return formulated response
```

---

### Flow B: Querying Documentation (RAG Flow)

```mermaid
sequenceDiagram
    participant User as React Frontend
    participant Go as Go Backend
    participant Gemini as Gemini AI
    participant DB as Supabase DB (pgvector)

    User->>Go: POST /api/v1/chat {"message": "How does IVR work?"}
    Note over Go: Intent detected as "knowledge_search"
    Go->>Gemini: Embed query ("How does IVR work?")
    Gemini-->>Go: 3072-dimensional vector
    Go->>DB: Query top 3 closest chunks (vector distance)
    DB-->>Go: Return chunks (content, title, url)
    Go->>Gemini: Send chunks + user question
    Gemini-->>Go: Summarized markdown response
    Go-->>User: Return response
```

### Flow C: Setting Config & Ingesting Wikis

```mermaid
sequenceDiagram
    participant User as React Frontend
    participant Go as Go Backend
    participant DB as Supabase DB
    participant ADO as Azure DevOps API
    participant Gemini as Gemini AI

    User->>Go: POST /api/v1/config/save {org, project, pat}
    Go->>DB: Upsert credentials into "user_configs" table
    Go-->>User: HTTP 200 (Success)
    
    Note over Go: Start background goroutine for wiki sync
    Go->>ADO: GET /_apis/wiki/wikis/.../pages (Fetch all wiki texts)
    ADO-->>Go: Return wiki pages
    loop For each page
        Go->>Go: Split text into chunks
        loop For each chunk
            Go->>Gemini: Generate Embedding Vector
            Gemini-->>Go: Return Vector
            Go->>DB: INSERT into "document_chunks"
        end
    end
    Note over Go: Sync Complete!
```
